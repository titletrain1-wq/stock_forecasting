# Real-Time v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:tdd per milestone. Steps use checkbox (`- [ ]`) syntax for tracking. This plan is executed by Toby (build lead); Creed + Meredith peer-review each milestone diff; god reviews each `M<n> done` report.

**Goal:** Add a real-time-capable display layer (live crypto via Coinbase WebSocket, ~15-min-delayed equities via yfinance intraday polling, streaming Streamlit chart) on top of the unchanged daily ML core.

**Architecture:** `worker.py` owns one Coinbase WebSocket connection and an equity intraday poller; both write to two new SQLite tables (`intraday_bars`, `live_quotes`). Streamlit reads those via `@st.fragment(run_every=...)` for a live-moving chart. The daily `ohlcv_bars` ledger, the ML models, the forecast ledger, and the evaluator are untouched. Health monitoring splits into a display path (intraday cadence) and a training-data path (trading calendar, unchanged).

**Tech Stack:** Python 3.12 · SQLModel/SQLite (WAL) · APScheduler · `websockets` (already locked, 16.1.1) or `websocket-client` (decided at M1 spike) · `httpx` · yfinance · Streamlit 1.62 (`st.fragment`) · Plotly · pytest · ruff · uv.

**Spec:** `docs/2026-09-01-realtime-v2-design.md` (v2). Base ML/ledger spec: `docs/2026-09-01-stock-forecasting-design.md` (v1, still authoritative for the frozen core).

**Research (do not re-derive):** `hive/shared/stock_forecasting/v2-research-apis.md` (Creed), `hive/shared/stock_forecasting/v2-research-arch.md` (Meredith).
